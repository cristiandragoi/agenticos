2. HG.Cash  -> DOCUMENTED READ-ONLY (balance + account status); R1 credential-
                scope concern; no cumulative-earnings field
================================================================================
Source: https://docs.hg.cash/api-reference/accounts/get-user-accounts
        (and the machine-readable https://docs.hg.cash/api-reference/openapi.yaml)

  paths:
  /accounts:
    get:
      tags: [Accounts]
      summary: Get User Accounts
      description: >
        Returns the authenticated user's accounts, including ledger balance,
        pending fees, net available balance (balance minus pending fees), and
        account status.
      operationId: getUserAccounts
      responses:
        '200':
          description: List of accounts
          content:
            application/json:
              schema:
                type: object
                properties:
                  data:
                    type: array
                    items:
                      type: object
                      properties:
                        id:          { type: string, format: uuid }
                        name:        { type: string }
                        balance:     { type: number, description: Account ledger balance rounded to 2 decimals }
                        pendingFees: { type: number, description: Fees accrued but not yet collected, rounded to 2 decimals }
                        netBalance:  { type: number, description: Available balance after pending fees (balance minus pending fees), rounded to 2 decimals }
                        status:      { type: string, description: Account lifecycle status,
                                       enum: [Operativa, Bloqueada, Cerrada] }
                        currency:    { type: string }
                        number:      { type: string }
                        alias:       { type: string }
                        platform:    { type: object }

  /account/{id}/balance:
    get:
      summary: Get Account Balance
      operationId: getAccountBalance
      description: >
        Returns the balance, pending fees, net available balance, currency, and
        account status for the authenticated user's account by ID.
      responses:
        '200':
          description: Account balance
          schema properties: id, balance, currency, pendingFees, netBalance,
            status (enum [Operativa, Bloqueada, Cerrada])

  servers:
    - url: https://hg.cash/api/v1        # Production server
    - url: http://dev.hg.cash/api/v1     # Development server
  security: [ bearerAuth ]
  components.securitySchemes.bearerAuth:
    type: http, scheme: bearer, bearerFormat: JWT
    description: User API authentication token with format: cash_<64-char-hex>

Source: https://docs.hg.cash/api-reference/webhooks/... (openapi.yaml)
  - To create cash-outs (money leaving your accounts), you must call the
    Cash Out endpoint: Create Transaction Request (Cash Out) (POST /transactions)

VERDICT:
  (i)  current balance  -> DOCUMENTED.  GET /accounts `balance` / `netBalance`,
                          or GET /account/{id}/balance `balance`.
  (ii) account status   -> DOCUMENTED.  `status` enum Operativa/Bloqueada/Cerrada.
  (iii) write/payout call required?  NO for the read itself -- GET only. BUT the
       same single bearer token (`cash_<64-hex>`, generated in account settings)
       authorises POST /transactions (cash out). There is NO documented
       read-only scope. So a monitor holding this token holds earning capability.
  (iv) cumulative earnings -> NOT DOCUMENTED. No earnings/cumulative field
       appears anywhere in the OpenAPI schema. `balance` is a ledger balance.
       The monitor's fourth compared field (earnings_total_cents) has no source.
  (v)  monitored entity -> the docs describe ARS accounts (CVU/CBU, Coelsa).
       Whether the entity behind proj-free-cash holds an HG.Cash account is a
       repo/operator fact, not a docs fact. BLOCKED.

VERDICT:
