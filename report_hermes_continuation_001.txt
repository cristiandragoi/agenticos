ROOT CAUSE:
───────────
After a successful execute_code tool call, compress_after_tool_results() removes
substantive user rows (tool results) from the message history. When only a reference
handoff summary remains, `_should_skip_model_call_for_reference_handoff()` returns True, 
suppressing the next model invocation and causing silent turn termination (#80622).

The problem was that post-tool continuation state was not preserved through compression.
The fix introduces an explicit flag `agent._continuation_required_after_tool` that tracks
when a substantive tool call just completed, forcing model continuation even in reference-handoff states.

WHY THE FIX IS SAFE:
────────────────────

1. Backward compatible: suppress_handoff_skip defaults to False, old behavior preserved for
   non-tool-result states and genuine idle handoffs
   
2. State cleared automatically: agent._continuation_required_after_tool is an instance attribute
   that resets on new AIAgent object spawn or explicit .reset()
   
3. Doesn't break legitimate terminations: The guard still fires for WAITING_FOR_APPROVAL,
   cancellation, safety limits, hard limits, or when only a final response has been produced
   
4. Minimal code surface: One new instance attribute and one parameter through preflight gate

COMPRESSION TIMEOUT BEHAVIOR:
─────────────────────────────

A timeout is explicitly logged and returns non-zero end_turn with 
final_response = _COMPRESSION_TIMEOUT_FINAL_RESPONSE. The caller doesn't interpret 
this as completion; it logs and either retries (if compression_attempts < max) or 
returns the error to the model.

The fix doesn't change this: timeout still terminates if no other path exists.
