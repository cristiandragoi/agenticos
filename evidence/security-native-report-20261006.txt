Native security boundary implementation — 6 October 2026

Implemented and empirically tested
The process-lifetime blocker now has a real Windows Job Object implementation. JobRunner creates the child suspended, assigns it before execution, denies breakaway, uses kill-on-close and resource limits, limits inherited handles, and confirms active process count zero after terminating descendants. Native tests cover parent exit, timeout, cancellation, output overflow, helper death, supervisor disconnect, nested jobs, native breakaway attempts and the process-count limit. This replaces a synthetic cleanup contract with actual controlled Windows OS evidence. No taskkill/WMI/PowerShell cleanup is used for these guarantees.

WindowsJob connects that helper to structured Git. ApprovedGitSupervisor verifies and consumes an exact signed approval before creating a job. It re-resolves supervisor-owned identity and carries the approved executable digest and repository path to dispatch. Tests execute harmless Git status operations in disposable repositories, then demonstrate refusal on replay, revocation, unavailable key and cross-worker substitution. Replay refusal survives database close and reopen.

Independent approval issuer
ApprovalIssuer.exe implements an out-of-band issuer using an existing per-user, non-exportable Windows CNG ECDSA P-256 key. It refuses shared/admin issuer identities, caller-selected manifests and unavailable keys. The fixed manifest must be administrator-owned and protected against ordinary writes. Issuance requires two secure-desktop Windows credential prompts authenticating the configured operator SID, with exact request details and expiry rechecked before signing.
The separate ApprovalEnroll.exe provides explicit offline bootstrap and outputs only public material. It was compiled, not used to enroll a real key. The server verifier handles public signatures only and now supports ES256 as well as the earlier synthetic Ed25519 protocol.
A separate test executable uses unnamed ephemeral CNG keys. Actual private-key export attempts fail, native signatures verify in Node, altered preview/arguments/scope are refused, and no human prompt or real credentials are used in these tests. This validates native protocol/crypto behavior, not trusted human presence or cross-account deployment.
